Values

pub fn content_disposition(StringView, inline? : Bool) -> String

The Content-Disposition value naming filename (RFC 6266).

A name that is plain ASCII goes out quoted; anything else — a space is not enough, but an accent, a quote, a newline, a byte outside ASCII — goes out as filename*, the only form that carries them and the only one a name cannot break out of.

inline asks the browser to show the content rather than save it.

example
println(@moonmime.content_disposition("menu.pdf"))
println(@moonmime.content_disposition("receta \"de la abuela\".pdf"))
attachment; filename="menu.pdf" attachment; filename*=utf-8''receta%20%22de%20la%20abuela%22.pdf
pub fn decode_charset(name~ : StringView, data~ : BytesView, charsets? : Map[String, &Charset]) -> String raise Refused

Read data as name says it was written. Unmapping octets become U+FFFD so that one bad byte costs one character and not the whole part.

mbt check
test {
  let text = @moonmime.decode_charset(name="iso-8859-1", data=b"\xe9") catch {
    _ => ""
  }
  inspect(text, content="é")
}
pub fn decode_words(StringView, charsets? : Map[String, &Charset]) -> String

Undo what encode_words did, and what every other mail library did too: encoded words are the one corner of a header everybody writes the same way.

Whitespace between two adjacent encoded words disappears, because that was folding and not content; whitespace next to ordinary text stays put.

mbt check
test {
  inspect(@moonmime.decode_words("=?utf-8?B?Q2Fmw6k=?="), content="Café")
}
pub fn encode_charset(name~ : StringView, text~ : StringView, charsets? : Map[String, &Charset]) -> Bytes raise Refused

Write text in name, refusing a character the set has no room for.

mbt check
test {
  let bytes = @moonmime.encode_charset(name="iso-8859-1", text="é") catch {
    _ => b""

  inspect(bytes == b"\xe9", content="true")

pub fn encode_words(StringView, charset? : String, encoding? : WordEncoding, column? : Int32, max? : Int32, charsets? : Map[String, &Charset]) -> String raise Refused

A header value written as encoded words, splitting whenever the next word would run past max.

Text that is already printable US-ASCII goes back unchanged: it needs no encoding, and writing it plainly is what keeps Subject: Hello readable in a raw view.

pub fn formdata(BytesView, StringView, limits? : Limits, strict? : Bool) -> Form raise Refused

Parse a multipart/form-data body (RFC 7578) given its boundary.

A part goes into the files when its Content-Disposition carries a filename and into the fields when it does not, which is the only thing distinguishing them on the wire.

example
let form = @moonmime.formdata(body, "----edge")
println(form.field("recipe").unwrap_or(""))  // chiles en nogada
chiles en nogada
pub fn guess_extension(StringView) -> String?

The extension most people use for a media type, with its dot; None when the type is not in the table. Parameters are ignored, so the value may be given with its charset.

pub fn guess_type(StringView) -> String

The media type a filename's extension implies; fallback for anything else.

The last dot wins, so archive.tar.gz resolves on gz. The table is the common part of the IANA media-type registry; a caller that knows its type names it rather than hoping the extension does.

example
println(@moonmime.guess_type("factura.PDF"))        // application/pdf
println(@moonmime.guess_type("archive.tar.gz"))     // application/gzip
application/pdf application/gzip
pub let limits : Limits

A thousand parts of a megabyte each — a bound wide enough for a usual form upload, tight enough to stop a body from asking for more than a server has. A caller that knows its own shape should say so.

pub fn media_type(StringView) -> MediaType

Parse a header value into a media type. Lenient: anything that is not a parameter is left out, so an empty or foreign value yields an empty essence rather than an error.

example
let mt = @moonmime.media_type("text/plain; charset=utf-8")
println(mt.essence)                    // text/plain
println(mt.param("charset").unwrap_or(""))  // utf-8
text/plain utf-8
pub fn multipart(BytesView, StringView, limits? : Limits, strict? : Bool) -> Array[Part] raise Refused

Split a multipart body into its parts (RFC 2046 §5.1) given its boundary.

Preamble and epilogue are dropped; the two CRLF before each delimiter belong to the delimiter, not to the part. A body that stops making sense returns what it read so far, unless strict says to refuse it.

This is the reader in PartsReader walked to its end: a caller that does not want the whole body in hand reads the parts as they arrive instead, and gets the same parts out.

example
let parts = @moonmime.multipart(body, "b")
println(parts.length())                       // 1
println(parts[0].header("content-type").unwrap_or(""))  // text/plain
1 text/plain
pub fn related(StringView, BytesView, limits? : Limits, strict? : Bool) -> Related raise Refused

Read a multipart/related body given the Content-Type that announces it.

The parameters come off the header, the parts off the body; root() is what ties the two together.

pub(all) struct MediaType

A media type: text/plain; charset=utf-8.

essence is the lowercased type/subtype; params keeps the parameters in order, names lowercased and quoted values unquoted. A malformed parameter is dropped rather than guessed at.

pub fn MediaType::parse(StringView) -> Self?

Parse a header value the way the MIME Sniffing standard reads one, and refuse the rest: None when the value is not a type/subtype of tokens.

Two readers, two jobs. media_type above takes whatever a server sent and keeps what it can; this one answers "is this a media type at all", which is the question worth asking when a value decides what a file is. A parameter whose name is not a token, or whose value cannot be written into a quoted string, is dropped; the first of two with the same name wins. Both are the standard's readings.

mbt check
test {
  let mt = @moonmime.MediaType::parse("Text/HTML; charset=\"utf-8\"").unwrap()
  inspect(mt.essence, content="text/html")
  inspect(mt.param("charset").unwrap_or(""), content="utf-8")
  inspect(
    @moonmime.MediaType::parse("text/html, text/plain") is None,
    content="true",
  )
}

pub(all) struct Multipart

A multipart body on its way out: the octets, the boundary that delimits them, and the subtype the two have to agree on.

The octets are what a Content-Type of content_type() describes and what multipart reads back with the same boundary.

kind : MultipartKind
boundary : String
body : Bytes
pub fn Multipart::content_type(Self) -> String

The Content-Type that goes with the body: the subtype, and the boundary the receiver needs to split it.

Written as a header value, so a boundary with a space in it — RFC 2046 allows the space, not as the last character — comes out quoted.

pub fn Multipart::new(Array[Part], boundary? : StringView, kind? : MultipartKind) -> Self raise Refused

Frame parts as a multipart body (RFC 2046 §5.1).

A part's headers go out in the order the part holds them, with a lowercased name — the shape a parse hands back — restored to Content-Type casing. A part with no headers at all is still a part: it is delimited like any other and its body is read back as it stands.

The boundary is generated when the caller gives none, from a fixed stem and a single pass over the parts, so the same parts always come out as the same octets and the boundary is proven absent from them rather than merely unlikely. A caller that gives one keeps control of what the receiver sees — the dash-stem browsers use, or a value it has already named elsewhere.

mbt check
test {
  let form = @moonmime.Form::new(fields=[{ name: "title", value: "a report", }])
  let body = form.encode(boundary="----edge")
  inspect(body.content_type(), content="multipart/form-data; boundary=----edge")
  let read = @moonmime.formdata(body.body[:], body.boundary)
  inspect(read.field("title").unwrap_or(""), content="a report")
}

type MultipartWriter

Writes a multipart body a part at a time: the delimiter and header block when a part begins, its body octets as they are handed over, and the closing delimiter when it ends.

The boundary is the caller's or a fixed stem, and the octets that would make it a delimiter inside a part are watched for as they go by: a body that holds the boundary is refused at that point rather than framed into a body the receiver would split somewhere else. A refusal cannot take back what the sink already holds, which is why a caller that cannot lose the octets passes a boundary of its own.

mbt check
test {
  let gathered = @moonmime.Gathered::new()
  let writer = @moonmime.MultipartWriter::new(gathered, boundary="b")
  inspect(writer.content_type(), content="multipart/mixed; boundary=b")
  writer.begin_part([("content-type", "text/plain")])
  writer.body(b"hola")
  writer.begin_part([("content-type", "text/html")])
  writer.body(b"<b>hola</b>")
  writer.close()
  let parts = @moonmime.multipart(gathered.bytes()[:], "b")
  inspect(parts.length(), content="2")
  inspect(parts[1].body, content="b\"<b>hola</b>\"")
}
pub fn MultipartWriter::begin_part(Self, Array[(String, String)]) -> Unit raise

Begin a part: its delimiter, then its header fields and the empty line that ends them.

A part is over when the next one begins; there is nothing to write between them but the delimiter, which carries the CRLF the receiver reads as the end of the previous body.

pub fn MultipartWriter::close(Self) -> Unit raise

pub fn MultipartWriter::content_type(Self) -> String

pub fn MultipartWriter::new(&Sink, boundary? : StringView, kind? : MultipartKind) -> Self raise Refused

The boundary is generated when the caller gives none: a fixed stem, so the same parts always frame the same way. Unlike a body written in one call it cannot be proven absent from parts that have not arrived yet, so it is watched for as they go by and a collision is refused.

type PartsReader

Reads a multipart body as it arrives: a part's header fields first, then its body, one chunk at a time.

The bound is part of the reading rather than a check afterwards: a part that passes its size is refused where it is crossed, and the octets after it are never pulled. What is already handed over cannot be taken back, so an unread remainder of a part is discarded — and still counted — before the next head is read.

mbt check
test {
  let reader = @moonmime.PartsReader::over(
    b"--b\r\nContent-Type: text/plain\r\n\r\nhola\r\n--b--\r\n", "b",
  )
  let head = reader.next_part().unwrap()
  inspect(head.header("content-type").unwrap_or(""), content="text/plain")
  inspect(reader.read().unwrap(), content="b\"hola\"")
  inspect(reader.read() is None, content="true")
  inspect(reader.next_part() is None, content="true")
}

pub(all) struct Related

A multipart/related body (RFC 2387): a compound object whose parts belong together, one of them the root the rest hang off.

The framing is the one every multipart subtype shares; what this type adds is the three parameters that say what the parts are — type for the media type of the root, start for the root's Content-ID, start-info passed through to that type — and the reading of start back into the part it names.

parts is what a reader found and what a writer frames; body() writes the octets those parts frame to, so a value read from a body that carried a preamble or a folded header writes back this library's own framing of the same parts.

type_ : String
start : String
start_info : String
boundary : String
parts : Array[Part]
pub fn Related::body(Self) -> Bytes

The body the parts frame to, delimited by this value's boundary.

pub fn Related::content_type(Self) -> String

The Content-Type that announces this body: boundary first, because the receiver cannot read the parts without it, then the three parameters RFC 2387 defines, in the order it names them. A parameter that was not given is not written.

pub fn Related::new(Array[Part], boundary? : StringView, type_? : String, start? : String, start_info? : String) -> Self raise Refused

A related body of parts.

The boundary works as it does for any other multipart body: the caller's, checked against RFC 2046 and against the parts, or generated from a stem stepped on until it is proven absent.

Left without parts the value is the header alone, which is what a caller streaming the body needs: the writer frames the parts, the value names them.

mbt check
test {
  let related = @moonmime.Related::new(
    [
      @moonmime.Part::{
        headers: [("content-id", "<root>"), ("content-type", "text/html")],
        body: b"<b>hola</b>",
      },
    ],
    boundary="b",
    type_="text/html",
    start="<root>",
  )
  inspect(
    related.content_type(),
    content="multipart/related; boundary=b; type=\"text/html\"; start=\"<root>\"",
  )
  inspect(related.root().unwrap().body, content="b\"<b>hola</b>\"")
}
pub fn Related::root(Self) -> Part?

The root part: the one start names by its Content-ID, or the first part when the header names none, which is RFC 2387's default.

None when the header names a part the body does not hold, which is a disagreement between the two halves rather than something to guess at.

Octets on their way out: what a caller's sink takes, a piece at a time.

The writer hands over the delimiter, the header block and the body octets of a part as it is given them, so a body larger than memory never stands in it.

pub(open) trait Source

A body arriving in pieces: the next octets, and None once there are none.

The chunk is the source's to size — a socket read, a slice of a file, a window of a buffer. A reader asks for one only when it needs the octets in it, which is what lets a bound stop a body where it is crossed instead of after the whole of it has been read.

mbt check
test {
  let source : &@moonmime.Source = @moonmime.Chunks::new(b"--b--\r\n")
  match source.next() {
    Some(chunk) => assert_eq(chunk, b"--b--\r\n")
    None => fail("the body was not handed over")
  }
  assert_eq(source.next() is None, true)
}

pub fn decode(BytesView, strict? : Bool) -> Bytes raise Refused

Decode quoted-printable.

=XY becomes the octet, = at the end of a line is the soft break it stands for and contributes nothing, and whitespace at the end of a line is dropped: a gateway further upstream may already have taken it, so keeping it here would not recover it.

strict turns the lenient last two readings into Encoding, which is what a mail filter that wants to see exactly what was signed asks for.

mbt check
test {
  let out = @qp.decode(b"a=3Db") catch { _ => b"" }
  inspect(out == b"a=b", content="true")
}
pub fn encode(BytesView) -> Bytes

Encode as quoted-printable. Lines are broken at 75 columns so that the soft break that ends one stays inside the 76 RFC 2045 allows, and line endings come out as CRLF whatever they arrived as.

mbt check
test {
  let out = @qp.encode(b"a=b")
  inspect(out == b"a=3Db", content="true")
}
