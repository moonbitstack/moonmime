From one header to a whole upload.

Each section builds on the last. Every block is a real program and every output below it is what it printed.

Install

Add the package to the module, then import it in the package that uses it.

shell
moon add moonbitstack/moonmime
moon.pkg
import {
  "moonbitstack/moonmime",
}

Now parse a Content-Type and read the pieces back.

main.mbt
let mt = @moonmime.media_type("text/html; charset=utf-8")
println(mt.essence)
println(mt.type_())
println(mt.param("charset").unwrap_or(""))
text/html text utf-8

Media types

media_type splits a header at its first ;. The essence is lowercased; the parameters keep their order and their case. A value it cannot make sense of is dropped rather than guessed at.

main.mbt
let mt = @moonmime.media_type("Text/HTML; charset=UTF-8")
println(mt.essence)
println(mt.type_())
println(mt.subtype())
println(mt.param("charset").unwrap_or(""))
println(mt.to_string())
text/html text html UTF-8 text/html; charset=UTF-8

A parameter value that is not a token goes back out quoted, so a boundary with spaces stays in one piece:

main.mbt
let mt = @moonmime.media_type("multipart/form-data; boundary=a b")
println(mt.param("boundary").unwrap_or(""))
println(mt.to_string())
a b multipart/form-data; boundary="a b"
Lenient by defaultAn empty or foreign value yields an empty essence instead of an error, so a server can read a header it does not understand without a branch.

Filenames and types

guess_type maps a filename to the media type its last extension implies; guess_extension goes the other way and gives the extension people actually use. The last dot wins, so a compound extension resolves on its tail.

main.mbt
println(@moonmime.guess_type("tacos-al-pastor.png"))
println(@moonmime.guess_type("factura.PDF"))
println(@moonmime.guess_type("archive.tar.gz"))
println(@moonmime.guess_type("name.unheard-of"))
println(@moonmime.guess_extension("audio/mpeg").unwrap_or(""))
println(@moonmime.guess_extension("text/plain; charset=utf-8").unwrap_or(""))
image/png application/pdf application/gzip application/octet-stream .mp3 .txt

Anything the registry has not heard of is application/octet-stream — the value fallback holds. A type with no common extension returns None.

Naming a download

content_disposition writes the header that names a file for the browser. A plain ASCII name stays quoted. A name with a quote, a newline, or a byte outside ASCII goes out as filename* (RFC 5987), which a browser reads back whole.

main.mbt
println(@moonmime.content_disposition("menu.pdf"))
println(@moonmime.content_disposition("receta \"de la abuela\".pdf"))
println(@moonmime.content_disposition("menu.pdf", inline=true))
attachment; filename="menu.pdf" attachment; filename*=utf-8''receta%20%22de%20la%20abuela%22.pdf inline; filename="menu.pdf"

On the way in, parse the header and ask for the filename. filename* wins over filename; a filename* that is not UTF-8 falls back to the plain one.

main.mbt
let d = @moonmime.Disposition::parse(
  "attachment; filename=\"fallback.txt\"; filename*=utf-8''r%C3%A9sum%C3%A9.txt",
)
println(d.kind)
println(d.param("filename").unwrap_or(""))
println(d.filename().unwrap_or(""))
attachment fallback.txt résumé.txt

Multipart

A multipart body is a boundary, a series of parts, and a closing boundary. multipart takes the body as bytes and the boundary without its leading dashes. Preamble and epilogue are dropped; the CRLF before each delimiter belongs to the delimiter, not the part.

main.mbt — helper
///| A string literal as the bytes a request would carry.
fn body(text : String) -> Bytes {
  let out : Array[Byte] = []
  for i = 0; i < text.length(); i = i + 1 {
    out.push((text.at(i).to_int() & 0xFF).to_byte())
  }
  Bytes::from_array(out)
}
main.mbt
let mail = body("--b\r\nContent-Type: text/plain\r\n\r\nhola\r\n--b--\r\n")
let parts = @moonmime.multipart(mail[:], "b")
println(parts.length())
println(parts[0].header("content-type").unwrap_or(""))
println(parts[0].body.length())
println(parts[0].content_type().unwrap().essence)
1 text/plain 4 text/plain

Each Part keeps its own headers and its body whole. content_type and disposition parse the two headers a form part carries.

Form data

formdata reads the same bytes as a form. A part with a filename in its Content-Disposition becomes an upload; a part without one becomes a text field. That is the only thing distinguishing them on the wire.

main.mbt — the body
let upload = "------edge\r\n" +
  "Content-Disposition: form-data; name=\"title\"\r\n\r\n" +
  "a report\r\n" +
  "------edge\r\n" +
  "Content-Disposition: form-data; name=\"tags\"\r\n\r\none\r\n" +
  "------edge\r\n" +
  "Content-Disposition: form-data; name=\"tags\"\r\n\r\ntwo\r\n" +
  "------edge\r\n" +
  "Content-Disposition: form-data; name=\"file\"; filename=\"notes.txt\"\r\n" +
  "Content-Type: text/plain\r\n" +
  "X-Checksum: abc\r\n\r\n" +
  "line one\r\nline two\r\n" +
  "------edge--\r\n"
main.mbt
let form = @moonmime.formdata(body(upload)[:], "----edge")
println(form.field("title").unwrap_or(""))
for tag in form.values("tags") {
  println(tag)
}
let file = form.file("file").unwrap()
println(file.filename)
println(file.content_type)
println(file.size())
println(file.header("x-checksum").unwrap_or(""))
a report one two notes.txt text/plain 18 abc

values keeps every value under a name — a set of checkboxes sends one name many times, and taking only the first silently drops the rest. An upload keeps its own headers, so a part's checksum or encoding is still there.

Bounds and strict reading

Both multipart and formdata take Limits — a thousand parts of a megabyte each by default. A body over its bound is refused whole, never truncated, because a handler given the first part of a larger body would be answering a request nobody sent.

main.mbt
try {
  let limited = @moonmime.formdata(
    body(upload)[:], "----edge", limits=@moonmime.Limits::new(parts=2),
  )
  println(limited.is_empty())
} catch {
  @moonmime.Parts(limit~) => println("refused: more than " + limit.to_string() + " parts")
  _ => println("refused")
}
refused: more than 2 parts

A body that stops making sense returns the parts read so far. strict turns that into Malformed at the byte where reading gave up.

main.mbt
let truncated = "------b\r\nContent-Disposition: form-data; name=\"a\"\r\n"
try {
  ignore(@moonmime.formdata(body(truncated)[:], "----b", strict=true))
} catch {
  @moonmime.Malformed(at~) => println("malformed at byte " + at.to_string())
  _ => println("refused")
}
malformed at byte 9
Two bounds, both neededA million empty parts and one enormous part are different ways of asking a server to allocate more than it has. Limits caps both.
